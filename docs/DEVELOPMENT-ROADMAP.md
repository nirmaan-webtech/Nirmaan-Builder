## Architecture decisions
- Product: independent WordPress plugin.
- Editor: React-based visual builder.
- Content storage: structured JSON plus WordPress data.
- Template structure: Header + Body + Footer.
- Default template: Whole Website.
- Assignment: conditional template system.
- Page editing: Edit with Nirmaan Builder.
- Frontend: server-rendered HTML.
- Responsive editing: desktop, tablet and mobile.
- Reusable designs: Library and Global Elements.
- Theme dependency: no mandatory dependency on one specific theme.
- Data safety: theme switching must not delete builder content.

## Additional scope requirements
- [x] Global Preset Synchronization: shared presets update all elements that use them.
- Builder Compatibility Layer: compatibility with existing themes, Gutenberg, third-party plugins and WooCommerce.
- Developer Extensibility: documented custom modules, hooks, filters, APIs and extension points.

## Definition of Done
A task is complete only when:
1. The feature is implemented, not merely represented by UI.
2. Input validation and authorization are implemented.
3. Relevant automated or manual tests pass.
4. Frontend behavior is verified for logged-in and logged-out visitors where applicable.
5. Documentation is updated.
